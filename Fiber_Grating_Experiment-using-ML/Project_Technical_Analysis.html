🔬 Fiber Bragg Grating (FBG) Sensing — ML Project: Complete Technical Deep-Dive

1. What is this Project About? (The Physics)

1.1 Fiber Bragg Grating (FBG) — The Sensor

A Fiber Bragg Grating is a type of optical sensor embedded inside a silica optical fiber. It works by having a periodic variation in the refractive index of the fiber core, which acts like a tiny mirror for a very specific wavelength of light — the Bragg wavelength (λB). All other wavelengths pass through.

The key physics equation is:

λ_B = 2 · n_eff · Λ

where:

  • λ_B = reflected (Bragg) wavelength
  • n_eff = effective refractive index of the fiber core
  • Λ = grating period (spacing between the refractive index variations)

1.2 Why FBGs Shift with Temperature and Strain

When the fiber is subjected to temperature change or mechanical strain, both n_eff and Λ change, which causes the Bragg wavelength to shift:

Stimulus What happens physically Effect on λB
Temperature ↑ Thermal expansion increases Λ; thermo-optic effect increases n_eff λB increases (red-shift)
Strain (tension) Fiber stretches → Λ increases; photo-elastic effect changes n_eff λB increases (red-shift)
The fundamental challenge: Both temperature and strain cause the Bragg wavelength to shift in the same direction. From a raw wavelength reading alone, you cannot tell whether the shift was caused by temperature, strain, or a combination of both. This is called the cross-sensitivity problem and is one of the biggest challenges in FBG sensing.

1.3 The Goal of the Project

The project aims to use Machine Learning to:

  1. Predict temperature from FBG wavelength data (Experiment 1)
  2. Predict strain from FBG wavelength data (Experiment 2)
  3. Simultaneously predict both temperature and strain from FBG wavelength data when both stimuli are present (Experiment 3 — the hardest case, addressing the cross-sensitivity problem)

4. Feature Engineering — The Core Technical Innovation

4.1 Why Raw Wavelength Alone is Not Enough

The raw Wavelength column is a single time-series signal. Feeding a single number (wavelength at time t) to a regression model gives the model very little information to work with. It cannot see:

  • Trends (is the wavelength going up or down?)
  • Volatility (how noisy is the signal?)
  • Distribution shape (is the signal symmetric or skewed?)
  • Rate of change (how fast is the wavelength shifting?)

4.2 Sliding Window Feature Extraction

The function sliding_features(x, windows=50) is the heart of the feature engineering pipeline:

dt = 0.5
def sliding_features(x, windows=50):
    df = pd.DataFrame({'x': x})
    df['mean']     = df['x'].rolling(windows).mean()
    df['std']      = df['x'].rolling(windows).std()
    df['slope']    = df['x'].diff(periods=5) / (dt * 5)
    df['skew']     = df['x'].rolling(windows).skew()
    df['kurtosis'] = df['x'].rolling(windows).kurt()
    return df.dropna().reset_index(drop=True)

This creates 5 new features from the raw wavelength signal using a sliding window of 50 samples:

Feature Formula Physical Meaning Why It's Used
mean Rolling mean over 50 samples The smoothed Bragg wavelength Removes high-frequency noise; captures the underlying trend. The Bragg wavelength shifts proportionally with temperature/strain, so the smoothed value directly correlates with the physical stimulus.
std Rolling standard deviation over 50 samples Signal volatility/noise Different temperature and strain conditions produce different levels of measurement noise. Noise increases when the system is in transition (e.g., temperature changing rapidly).
slope diff(periods=5) / (dt * 5) = rate of change over 5 time steps How fast the wavelength is changing (nm/sec) Captures the dynamics — a rapidly changing wavelength implies a rapidly changing stimulus. This is critical for time-series regression because it gives the model directional information.
skew Rolling skewness over 50 samples Asymmetry of the wavelength distribution If the wavelength is trending in one direction, the distribution of recent values will be skewed. This helps distinguish steady-state from transient conditions.
kurtosis Rolling kurtosis over 50 samples "Tailedness" of the distribution High kurtosis means extreme outlier readings are occurring (e.g., measurement spikes during rapid temperature changes). Helps characterize the stability of the measurement.
Why a window of 50? With a 5 Hz sampling rate, 50 samples = 10 seconds of data. This is a reasonable time window for smoothing physical processes (temperature changes in lab settings are slow — minutes to hours). Too small a window → noisy features. Too large → features lag behind the actual physical changes.
Why diff(periods=5) for slope? Differentiating adjacent samples amplifies noise. Using 5 sample spacing (1 second) provides a cleaner estimate of the rate of change while still being responsive enough to capture dynamics.

4.3 The shift Feature

After the sliding window features, a wavelength shift column is added:

featured_temp['shift'] = featured_temp['Wavelength'] - featured_temp['Wavelength'].iloc[0]

This computes how far the current wavelength has moved from the initial reading (baseline).

Why this is the most important feature: The Bragg wavelength shift (ΔλB) is directly proportional to temperature change (ΔT) and strain (Δε) by the fundamental FBG equation:
Δλ_B = λ_B · (α + ξ) · ΔT + λ_B · (1 - pe) · Δε
where α = thermal expansion coefficient, ξ = thermo-optic coefficient, pe = photo-elastic constant.
So shift is the single most physically meaningful feature for predicting temperature and strain.

4.4 Final Feature Set

After feature engineering, each dataset has 7 features per sample:

# Feature Description
1 Wavelength Raw Bragg wavelength at time t
2 mean Rolling 50-sample mean
3 std Rolling 50-sample standard deviation
4 slope Rate of change (nm/sec)
5 skew Rolling 50-sample skewness
6 kurtosis Rolling 50-sample kurtosis
7 shift Wavelength shift from baseline

5. Target Variable Construction

5.1 Synthetic Labels

A critical detail: the datasets do not contain actual temperature/strain measurements. Instead, the target values are synthetically generated using np.linspace():

y_temp    = np.linspace(20, 80, len(featured_temp))    # Temperature: 20°C → 80°C
y_strain  = np.linspace(0, 1000, len(featured_strain))  # Strain: 0 → 1000 µε
Major assumption: This assumes the temperature/strain changed perfectly linearly over the duration of each experiment. In reality, physical processes (heating, mechanical loading) rarely produce perfectly linear ramps. This is a simplification that could introduce systematic error into the model.

For Experiment 3 (both stimuli), both targets are stacked:

y_both = np.column_stack([y_temp_mix, y_strain_mix])

This creates a multi-output regression problem (predict 2 values simultaneously).

6. Model Selection & Training

6.1 Method 1: Simple Train/Test Split with Linear Regression & Random Forest

Train/Test Split

train_test_split(x, y, test_size=0.2, random_state=50)

80% training, 20% testing, with a fixed random seed for reproducibility.

Models Used

Dataset Model Why This Model
Temperature (Exp 1) LinearRegression FBG wavelength shift is linearly proportional to temperature change (ΔT). This is physics-based model selection — the relationship is known to be linear, so linear regression is the natural first choice.
Strain (Exp 2) LinearRegression Similarly, wavelength shift is linearly proportional to strain (Δε). Same physics reasoning.
Both (Exp 3) MultiOutputRegressor(RandomForestRegressor()) When both temperature and strain act simultaneously, the relationship becomes more complex (cross-sensitivity). A Random Forest was chosen because: (a) it can capture non-linear interactions between features, (b) it naturally handles multi-output regression via MultiOutputRegressor, and (c) it's robust to overfitting with default parameters.
Why not use Linear Regression for Experiment 3 too? Because with both stimuli acting simultaneously, the simple linear relationship breaks down. The cross-sensitivity means you need a model that can learn complex feature interactions. Random Forest builds many decision trees, each looking at different feature subsets, and averages their predictions — this gives it the ability to decompose the entangled temperature/strain signal.

Method 1 Results

6.2 Method 2: GroupKFold + GridSearchCV (Nested Cross-Validation)

This is the more rigorous approach.

Why GroupKFold Instead of Regular KFold?

grp_temp = np.arange(len(featured_temp)) % 3

The data points are assigned to 3 groups cyclically (0, 1, 2, 0, 1, 2, ...). GroupKFold ensures that:

  • All data points in the same group go into either training OR testing, never both
  • This prevents temporal leakage: adjacent time points have nearly identical feature values (autocorrelation), so random splitting would put virtually identical points in both train and test sets, artificially inflating performance
Why this matters: FBG time-series data is highly autocorrelated — the wavelength at time t is almost identical to the wavelength at time t+0.2s. If you do a random 80/20 split, the model "memorizes" the time-series and gets unrealistically high scores. GroupKFold with cyclical grouping forces the model to generalize across different time segments.

GridSearchCV for Hyperparameter Tuning

param_grid = {
    "n_estimators": [100, 200, 300],
    "max_depth": [5, 10, None]
}
model = RandomForestRegressor(random_state=42)
inner_cv = GroupKFold(n_splits=2)
grid = GridSearchCV(model, param_grid, cv=inner_cv, scoring="neg_mean_squared_error")

This searches over a grid of:

  • n_estimators = [100, 200, 300] (number of trees in the forest)
  • max_depth = [5, 10, None] (maximum depth of each tree)

Inner CV uses 2-fold GroupKFold to evaluate each hyperparameter combination, selecting the one with the lowest MSE.

Why Random Forest for all three datasets in Method 2? In Method 1, Linear Regression was used for Experiments 1 & 2. In Method 2, all three use Random Forest with GridSearchCV. This is a deliberate upgrade — even though the physics is linear for single-stimulus cases, Random Forest can still capture these linear relationships while also being robust to any non-linearities in the engineered features.

Method 2 Results (Random Forest + GridSearchCV + GroupKFold)

Dataset MAE MSE RMSE R² Score
Temperature 0.16 0.15 0.38 99.951%
Strain 5.27 107.91 10.39 99.870%
Both (combined) 2.22 47.44 6.89 99.886%
Dramatic improvement over Method 1! The R² scores jump from ~92-94% to ~99.9%. This is because:
1. Random Forest captures non-linearities in the features better than Linear Regression
2. GridSearchCV found optimal hyperparameters (the best model was RandomForestRegressor(n_estimators=300, max_depth=None) for all three datasets)
3. The more structured cross-validation (GroupKFold) actually produces more honest and better-calibrated models

7. Evaluation Metrics Explained

Metric Formula Interpretation
MAE (Mean Absolute Error) mean(|y_true - y_pred|) Average absolute prediction error. Easy to interpret — "on average, the prediction is off by X units".
MSE (Mean Squared Error) mean((y_true - y_pred)²) Average squared error. Penalizes large errors more heavily than small ones.
RMSE (Root Mean Squared Error) sqrt(MSE) Same units as the target variable. More interpretable than MSE, still penalizes outlier errors.
R² Score 1 - SS_res / SS_tot Proportion of variance explained by the model. 1.0 = perfect, 0.0 = no better than predicting the mean.

9. Challenges & Limitations

9.1 Cross-Sensitivity Problem

The biggest challenge in FBG sensing: both temperature and strain cause wavelength shifts in the same direction. The project addresses this by using multi-output Random Forest regression with rich feature engineering. The 99.886% R² on the "Both" dataset suggests this approach works well.

9.2 Synthetic Target Variables

The target values (temperature, strain) are generated with np.linspace(), assuming perfectly linear ramps. In real-world applications, the actual temperature/strain values would come from reference sensors (thermocouples, strain gauges), which would introduce their own measurement uncertainties.

9.3 No External Validation

The model is trained and tested on data from the same experimental session. A truly robust model would need to be validated on data from different experiments, different FBG sensors, or different environmental conditions.

9.4 Feature Engineering Assumptions

  • The 50-sample rolling window is hand-tuned and may not be optimal for all scenarios
  • The slope calculation uses a fixed dt = 0.5 (not the actual time delta between samples, which is ~0.2s) — this means the slope values are scaled differently than the actual physical rate of change

9.5 Temporal Autocorrelation

Even with GroupKFold, the cyclical grouping (% 3) still allows "nearby" time points to leak across folds. A more rigorous approach would use time-based splits (train on first 70%, test on last 30%) or blocked cross-validation.

12. Key Takeaways

  1. Feature engineering is everything: The raw wavelength signal is nearly useless on its own. The sliding window statistical features (mean, std, slope, skew, kurtosis) and the baseline shift transform a single noisy time-series into a rich 7-dimensional feature space that ML models can effectively learn from.
  2. Model selection should be guided by physics: Linear Regression for single-stimulus (linear physics), Random Forest for multi-stimulus (cross-sensitivity → non-linear interactions).
  3. Proper cross-validation is critical for time-series data: Simple random splitting overestimates performance. GroupKFold prevents temporal leakage.
  4. Hyperparameter tuning matters: GridSearchCV improved R² from ~94% to ~99.9% for temperature prediction by finding optimal Random Forest parameters.
  5. The cross-sensitivity challenge is solvable with ML: The 99.886% R² on simultaneous temperature + strain prediction demonstrates that ML feature engineering can decode the entangled wavelength signal — something that is extremely difficult with traditional analytical methods.
